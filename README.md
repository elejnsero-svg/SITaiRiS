# Служба доставки — расчёт стоимости и срока (Вариант 5)

Консольное приложение на C# (.NET 6+, язык C# 7.3), демонстрирующее
применение паттернов проектирования **Strategy** и **Factory Method**.

**Автор:** Иванов Иван Иванович, группа ИС-21  
**Дисциплина:** Паттерны программирования  
**Вариант:** № 5 — «Служба доставки»

---

## 📋 Описание задания

Нужно реализовать службу доставки, которая:

- рассчитывает **стоимость** и **срок** доставки посылки;
- поддерживает разные способы: **наземный**, **авиа**, **морской**, **курьерский**;
- позволяет **добавлять новые способы без переписывания старого кода**;
- создаёт подходящий **транспорт по типу перевозки**.

**Ограничения:**
- консольное приложение на C# (.NET 6+), целевая версия языка — C# 7.3;
- код разбит по папкам `Models`, `Patterns`, `Program`;
- `Main` только запускает демонстрацию, вся логика — в классах;
- каждый паттерн демонстрируется минимум одним сценарием с понятным выводом.

**Что демонстрируется:**
1. Расчёт одной и той же посылки наземным, авиа, морским и курьерским способом.
2. Подмена стратегии расчёта **на лету** (без пересоздания `DeliveryService`).
3. Добавление нового способа — **доставка дроном** — без правок существующих классов.
4. Создание транспорта по типу перевозки через **фабрики**.

## Использованные паттерны и их обоснование

### 1. Strategy (Стратегия)

**Что это.** Паттерн, при котором семейство взаимозаменяемых алгоритмов выносится за пределы клиента, а клиент работает через общий интерфейс и может менять алгоритм во время работы.

**Как реализовано.**
- Интерфейс `IDeliveryStrategy` с методами `Name` и `Calculate(Parcel): DeliveryResult`.
- Реализации: `GroundDeliveryStrategy`, `AirDeliveryStrategy`, `SeaDeliveryStrategy`, `CourierDeliveryStrategy`, `DroneDeliveryStrategy`.
- `DeliveryService` хранит `_strategy` и подменяет её через `SetStrategy()`.

**Какую проблему решает в приложении.**
- Без паттерна `DeliveryService` представлял бы собой «божественный» `switch(type)` с формулами всех способов. Добавление нового способа = правка этого метода, регрессия всего расчёта, риск ошибок.
- Со стратегией **расчёт отделён от контекста**: каждая формула живёт в своём классе. Добавление нового способа — новый класс + одна строка `SetStrategy`. Существующие классы не меняются — соблюдается **Open/Closed Principle**.
- Алгоритмы взаимозаменяемы **на лету** (можно сравнивать варианты, не пересоздавая сервис).

**Что было бы без него.** Большой `switch` / `if-else` в центральном классе, дублирование проверок, невозможность переиспользовать формулы вне приложения, тестирование каждого способа завязано на всём `DeliveryService`.

---

### 2. Factory Method (Фабричный метод)

**Что это.** Порождающий паттерн, при котором создание объекта делегируется наследникам (или отдельным классам-фабрикам) через общий интерфейс.

**Как реализовано.**
- Интерфейс `ITransportFactory` с методом `CreateTransport(): Transport`.
- Реализации: `GroundTransportFactory`, `AirTransportFactory`, `SeaTransportFactory`, `CourierTransportFactory`, `DroneTransportFactory`.
- Клиент (`DeliveryService.ShowTransport`) принимает `ITransportFactory` и вызывает `CreateTransport()`, не зная конкретный класс.

**Какую проблему решает в приложении.**
- Клиент **не зависит от конкретных классов** `Truck`, `Airplane`, `Drone`. Логика `new Truck()` изолирована в фабрике.
- **Добавление нового транспорта** (дрон) не требует правок ни в `DeliveryService`, ни в существующих фабриках — только новый класс `Drone` + `DroneTransportFactory`.
- Единая точка создания объектов — если у транспорта появится конструктор с параметрами (госномер, грузоподъёмность), правится **одна** фабрика, а не 100 мест в коде.

**Что было бы без него.** `new Truck()` / `new Airplane()` разбросаны по клиентскому коду. Замена или расширение модельного ряда транспорта → каскад правок во всех местах, где создаётся транспорт. Клиент жёстко связан с реализациями.

---

### Совместный эффект

Strategy отвечает за **поведение** (как считать), Factory Method — за **создание** (какой транспорт использовать). Вместе они дают архитектуру, где:
- **добавление способа** = новый класс стратегии (и, при желании, фабрика транспорта);
- **добавление транспорта** = новый класс + фабрика;
- **существующий код не меняется** — что и было требованием варианта.

## Инструкция по запуску

### Требования
- .NET SDK **6.0** или новее ([скачать](https://dotnet.microsoft.com/download)).
- Любой терминал: PowerShell, bash, zsh.

### Запуск

```bash
# 1. Клонировать репозиторий
git clone https://github.com/USERNAME/delivery-app.git
cd delivery-app/DeliveryApp

# 2. Собрать проект
dotnet build

# 3. Запустить демонстрацию
dotnet run
```
